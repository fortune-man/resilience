요구사항
1. 회원 서비스 member
   1.1 책임: 고객의 회원 가입, 로그인, 정보 수정, 탈퇴를 관리한다.
   1.2 주요 기능: JWT(JSON Web Token) 기반의 인증(Authentication)을 처리하며, API 게이트웨이와 연동하여 시스템 전반의 사용자 식별을 책임진다.
   1.3 특징 : 모든 서비스에서 가장 기본이 되는 데이터(회원 ID, 이름, 등급)를 제공한다.
2. 상품 item
   2.1 책임: 상품 정보(이름, 가격, 설명)를 관리하고, 가장 중요한 '재고(Inventory)'를 관리한다.
   2.2 주요 기능: 상품 전시, 상세 정보 조회, 그리고 '주문'시 재고 차감을 담당한다.
   2.3 특징: '상품 상세 조회'처럼 읽기(Read) 요청이 압도적으로 많고, '재고 차감'처럼 쓰기(Write) 경쟁이 치열하게 발생한다. CQRS 및 캐싱 패턴을 적용하기에 가장 이상적인 도메인이다.
3. 주문 order 
   3.1 책임 : 고객의 '장바구니'부터 '주문 생성'까지의 핵심 비즈니스 로직을 담당한다.
   3.2 주요 기능 : 주문을 생성(Create)하고, 주문 내역을 조회(Read)한다.
   3.3 특징: MSA에서 가장 복잡한 서비스다. 주문을 생성하기 위해 '회원' 정보가 필요하고, 상품의 재고를 확인해야 하며, '결제'를 요청하고, '배송'을 위한 이벤트를 발행해야 한다. SAGA 패턴을 이용한 분산 트랜잭션의 중심이 된다. 
4. 결제 pay
   4.1 책임 : 실제 외부 PG(Payment Gateway)사와 연동하여 결제를 승인하고 취소하는 역할을 담당한다.
   4.2 주요 기능 : '주문' 서비스의 요청을 받아 결제를 시도하고, 그 결과를 '주문' 서비스에 통보한다.
   4.3 특징 SAGA 패턴에서 '주문'에 대한 보상 트랜잭션(결제 취소)을 수행하는 중요한 역할을 맡는다.
5. 배송 delivery
   5.1 책임: 주문이 결제 완료되었을 때, 상품 배송을 시작하고 배송 상태(준비 중, 배송 중, 배송 완료)를 추적한다.
   5.2 주요 기능: Kafka를 통해 '주문 완료'이벤트를 구독(Subscribe)하여 배송 프로세스를 시작한다
   5.3 특징: 주문 서비스와 완벽하게 분리된 비동기(Async) 이벤트 기반 아키텍처 (EDA)를 연습하기 위한 핵심 도메인이다.

- feign 으로 동키 통신을 하고, Kafka로 비동기 이벤트를 주고받으며 Kubernetes와 Istio 위에서 함께 동작할 것이다.
