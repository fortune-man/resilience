수학능력시험 응시자를 위한 원서 접수 인증 시스템

1. 개요 - 필요성
취미로 프로그래밍 공모전에 참여하며 정보보안 경력을 쌓은게 아까워
지역 소득 격차로 인한 교육 차별 해소의 필요성을 채울 수 있는 EBS 프로젝트를 기획했습니다.

처음엔 평소 관심갖고 있던 msa나 우아한 장애 격리 시스템 개발의 필요성이 있을지 알아봤고
실습을 통해 실제 필요가 있는 기능과 고민을 해야 가치있는 시간이 될 것 같아
정보보안 관련 경력을 살릴 수 있는 인증 기능 개발에 초점을 두고

EBS 교육을 수강하는 수강생의 수학능력시험 응시 시기 
이용자가 몰려 과부하가 발생하거나
대리 접수 및 부정 행위 대처를 고려한 상황을 고려했습니다.


2. 구조 설계 - 단일 책임 원칙 - 자연스러운 mvc 패턴 학습의 필요성 발생
  2.1 Service - 입력된 학생 정보가 본인이 맞는지 확인 요청을 보내야 하고 검증된 정보를 전달하고 예외 상황에 대처하기 위해 존재하는 역할
  2.2 Repository - 요청 받은 정보와 저장되어 있는 정보의 일치성을 확인하기 위해 존재하는 역할
  2.3 App - 전달받은 정보를 사용자가 알 수 있게 보여주는 역할(view)로 보입니다.
  2.4 고민할 꺼리 : 요구사항을 충족하기 위해 어떤 로직을 작성해야 할지? 그리고 어떤 자료구조를 결정해야 할지? 무엇을 위해서 그 로직과 자료구조를 사용해야 할지?
  2.5 스스로 이야기 한 것들에 대해 정말 충분히 이해하고 있는지?

3. 처리 흐름
  3.1 앱에서 사용자가 개인정보를 입력합니다. (휴대폰 본인인증 안내)
  3.2 휴대폰 본인인증 안내 - 인증방법 선택 (pass, qr 코드, 문자 sms 인증) - 통신사 선택 - 본인확인 이용 동의(개인정보 보호 이용 동의 정보가 포함된 내용을 클릭하면 열고 닫기로 확인 가능 )
  3.3 입력 - 통신사 선택
    3.3.1 pass 앱 인증 (이름, 휴대폰 번호, 보안문자 입력) - pass 앱 알림 확인 - 인증 완료  
    3.3.2 QR 코드 인증 - QR코드 카메라 인식 또는 일련문자 유효기간 내 입력 - 인증 완료
    3.3.2 휴대폰 번호 인증 - 이름, 주민등록번호 앞자리 전체 뒷자리 하나까지, 휴대폰 번호, 보안문자 입력 - 인증번호 전송 - 사용자가 입력한 인증번호 확인 - 인증 완료

4. 예외 상황
 4.1 특정 시간 이용자 부하로 인한 다운타임 (시험 종료 직후 가채점 및 등급 확인 목적, 수능 성적 발표일, 수능 원수 접서 당일, 수시 및 정시 모의 마감 직전)
 4.2 대리응시자 접수 검증
5. 필요 있는 로직
 5.1 입력 - 조회 - 확인 요청 - 검증 - 상태 확인 - 응답 (==와 &&, 논리 연산자)
 5.2 다운타임이라는 병목에 대처할 필요가 있는 기술 사용 - 대기열, 우아한 종료..등 (비교 연산자 <= 를 통해 실시간 트래픽이 임계치를 넘으면 db나 다음 로직으로 진입시키지 않고 즉시 거부를 응답하는 간이 대기열 / 차단 구조)
 5.3 대리 응시자 제한, 비정상요청 대처 (주민등록번호 뒷자리가 특수문자인 경우, 또는 저장된 응시자 정보와 입력된 정보의 불일치성 및 비정상 경우가 확인되어 거부 응답하는 구조)
 5.4 가급적 기본기 누적 효과를 위한 기초 연산자 최대한 활용부터
