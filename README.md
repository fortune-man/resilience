2. 구조 설계 - 단일 책임 원칙 - 자연스러운 mvc 패턴 학습의 필요성 발생
  2.1 Service - 입력된 학생 정보가 본인이 맞는지 확인 요청을 보내야 하고 검증된 정보를 전달하고 예외 상황에 대처하기 위해 존재하는 역할
  2.2 Repository - 요청 받은 정보와 저장되어 있는 정보의 일치성을 확인하기 위해 존재하는 역할
  2.3 App - 전달받은 정보를 사용자가 알 수 있게 보여주는 역할(view)로 보입니다.
  2.4 고민할 꺼리 : 요구사항을 충족하기 위해 어떤 로직을 작성해야 할지? 그리고 어떤 자료구조를 결정해야 할지? 무엇을 위해서 그 로직과 자료구조를 사용해야 할지?
  2.5 스스로 이야기 한 것들에 대해 정말 충분히 이해하고 있는지?

3. 처리 흐름
  3.1 앱에서 사용자가 개인정보를 입력합니다. (휴대폰 본인인증 안내)
  3.2 휴대폰 본인인증 안내 - 인증방법 선택 (pass, qr 코드, 문자 sms 인증) - 통신사 선택 - 본인확인 이용 동의(개인정보 보호 이용 동의 정보가 포함된 내용을 클릭하면 열고 닫기로 확인 가능 )
  3.3 입력 - 통신사 선택
    3.3.1 pass 앱 인증 (이름, 휴대폰 번호, 보안문자 입력) - pass 앱 알림 확인 - 인증 완료  
    3.3.2 QR 코드 인증 - QR코드 카메라 인식 또는 일련문자 유효기간 내 입력 - 인증 완료
    3.3.2 휴대폰 번호 인증 - 이름, 주민등록번호 앞자리 전체 뒷자리 하나까지, 휴대폰 번호, 보안문자 입력 - 인증번호 전송 - 사용자가 입력한 인증번호 확인 - 인증 완료
